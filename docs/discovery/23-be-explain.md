## What exists today

Two-tier explanation system (`app/explain.py`):

1. **Tier 1 — deterministic template** (`render_template`, explain.py:211–255). Built **only** from `PredictionOut` + canonical report text. Asserts, in order:
   - Trigger line: `Review trigger: triage score {score:.2f} crossed the {thr:.2f} review threshold.` or `Triage score {score:.2f} is below the {thr:.2f} review threshold.` where `thr` is the classifier's **tuned operating point** passed in by the route (`threshold=flag_threshold(clf)`, routes.py:128/259) — measured **0.6581** on this artifact (metrics.json `operating_point_test_tuned`, raw 0.7464 mapped through temperature 1.6484, classifier.py:374–400).
   - Implicated IOGP rules: `prob >= RULE_DISPLAY[key]["threshold"]` where RealOnnxClassifier overwrote the defaults at load with per-rule F1-tuned thresholds 0.54–0.95 (classifier.py:283–291, schemas.py:27–48).
   - Well-control tag; quoted evidence phrases; honest-abstention line (`"No reliable supporting phrase could be isolated; inspect the full report before disposition."`, explain.py:250); triggered advisory gates.
2. **Tier 2 — optional Ollama rewording** (`ollama_reword`, explain.py:307–355). `POST /api/chat` to `qwen3:4b` with C10 contract (`stream:false, think:false, format:<JSON schema>, temperature:0, num_predict:300` — the schema `format` is the anti-thinking control). **The LLM never sees the report** — the user message carries only the template (explain.py:118–122). It can therefore only paraphrase what the template asserted; it cannot invent report content the template didn't contain. Latency budget: 8 s per attempt, 1 corrective retry, then `None` → silent template fallback.

**Cache:** `precomputed` SQLite table (storage.py:96–100), key `explain:sha256(text\0model_version\0repr(threshold)\0EXPLANATION_VERSION)` (explain.py:134–149); ollama-sourced entries served "verbatim forever", template-only entries for `FALLBACK_TTL_S=300s` then one LLM upgrade retry (explain.py:383–388). A precompute harness exists (`artifacts/explanations/precompute.py`, concurrency 4, resume-safe, gates-attached "live-path fidelity").

**Consumption:** `POST /classify?explain=1` attaches to the prediction (never persisted, schemas.py:97–99); `GET /api/reports/{id}/explanation` recomputes on demand with the tuned threshold. The paste path hardcodes `llm=0` (api.ts:279) — template-only, deliberately. The triage-card expander fetches the stored-report explanation lazily with a 12 s client timeout (api.ts:359) and renders `reworded ?? template` (triage-card.tsx:278), with a small `"phrased by local LLM" · cached` provenance label (triage-card.tsx:260–265, phrasebook.ts:53,152).

## Findings

**1. [BLOCKER] The entire explanation precompute cache is dead; the demo's "never waits on a live LLM call" doctrine is factually broken today.**
`demo_pre.db` carries **63 explain-cache entries (55 `source:"ollama"`, 8 `source:"template"`) built 2026-09-09 22:46–22:48** (measured by sqlite inspection of `/tmp/qa_exp.db`). The current `explain_key` (explain.py:134–149) hashes `text \0 model_version \0 repr(threshold) \0 EXPLANATION_VERSION` — but the demo-era code (commit `4cd1b09`, `git show 4cd1b09:app/explain.py:88–93`) hashed only `text \0 model_version \0 repr(threshold)` with **no version component**. Adding a constant suffix to a hash input changes every digest, so **all 63 entries are permanently unreachable**. Live confirmation on the isolated stack: `GET /api/reports/4546/4544/4542/explanation` all returned `"cached": false` (`source: "template"`, 11–38 ms because ollama is down and fail-fast). Offline confirmation: recomputing the current key over all 4,548 stored report texts produces **0 hits** against the 63 cached keys (grid-searched 7 thresholds × 3 version strings). Consequence: every `GET /reports/{id}/explanation` on the demo corpus attempts the LLM. With ollama *down* that is fail-fast; with ollama *up but slow*, each expand is a 16 s stall (measured, finding 4) — the opposite of what the precompute doctrine guarantees (explain.py:20, precompute.py:2–3).

**2. [MAJOR] Anti-hallucination validation enforces the triage score but not the rule-signal numbers or the gate advisories.**
`_validate` (explain.py:282–304) checks: (a) digit-boundary-anchored triage score preserved — good, with an honest SEV2 comment about `"10.83"`/`"0.833"` mutations; (b) anti-chain-of-thought regex on the first 300 chars (explain.py:275–279, observed-live rationale quoted); (c) `spans_quoted` exact case-sensitive substrings; (d) **anything in double quotes in the prose** validated verbatim against the report (explain.py:296–303). What is **not** validated: the rule probabilities the paragraph restates (`"Hot Work (0.71)"` mutated to `(0.17)` passes); whether the gate advisory lines survive the rewording; whether `spans_quoted` is non-empty (an empty array plus an evidence-free paragraph passes). The system prompt's core rule is "keep every number exactly as given" (explain.py:116) — enforcement covers 1 of the ~4–8 numbers a verdict displays. Hostile-reviewer framing: "you regex-guard the headline number and trust a 4B model with the rest."

**3. [MAJOR] The reworded text *replaces* the template in the UI; the component's own docstring is false.**
`triage-card.tsx:278` renders `{explanation.reworded ?? explanation.template}`, while the docstring at triage-card.tsx:209–212 claims "The template is the deterministic floor and always renders once loaded; the ollama rewording is additive". It is not additive — when the LLM succeeded, the floor text is never rendered; the only provenance is a 12 px mono label `"phrased by local LLM"` (triage-card.tsx:260–265). The validated `spans_quoted` are never rendered anywhere client-side (only the classifier's `evidence_spans` get highlighted, triage-card.tsx:161). A hostile reviewer cannot see the verified-floor text, so the paraphrase is audited instead of the contract.

**4. [MAJOR] Worst-case explain latency is 2× the timeout (measured 17.5 s), and the client aborts at 12 s — the doc comment is wrong by 2×.**
`routes.py:102–104` promises "every call is bounded by the 8 s timeout and falls back silently." In fact the timeout applies **per attempt** (inside `_http_transport` urlopen, explain.py:258–269) and `ollama_reword` loops **twice** (explain.py:329–342). Measured this session against a connection-squatting stub on 127.0.0.1:8299 with `SIF_EXPLAIN_TIMEOUT=8`: `POST /api/classify?explain=1&llm=1` → **17.5 s**; `GET /api/reports/4546/explanation` → **16.0 s**. The client (`getExplanation`, api.ts:357–363) aborts at **12 s**, so under a hung LLM the reviewer sees `explanationUnavailable` and *not even the template*, while the server continues computing. With ollama fully down the failure is fast (connection refused → both attempts fail in ms; measured 0.3–0.4 s end-to-end) — the dangerous mode is specifically "up but slow."

**5. [MAJOR] There is no explainability audit log: you cannot prove WHAT was shown to a reviewer and WHEN.**
The compliance-critical requirement is unmet by design. The `overrides` table stores the reviewer's decision — `report_id, field, old_value, new_value, labeler, source, rationale, created_at` (storage.py:81–91, INSERT at 362–371) — but never the explanation content presented at decision time. `PredictionOut.explanation` is explicitly "never persisted" (schemas.py:97–99), and `GET /reports/{id}/explanation` is compute-on-demand with no serving log (routes.py:244–260). Since template entries are deterministic this is *partially* reconstructible from the stored prediction + current code — but ollama-sourced entries are build-time artifacts that can be replaced later (INSERT OR REPLACE, storage.py:620), so future-you cannot reconstruct what the reviewer actually saw when they confirmed a safety-critical flag. OISD-style incident scrutiny would ask for exactly this record.

**6. [MAJOR] Mock fixtures fabricate LLM-sourced explanations attached to real row ids — invented reasoning displayed with machine provenance on a safety surface.**
`dashboard/src/lib/mock.ts:144–208` ships `MOCK_EXPLANATIONS` keyed by **real** row ids 2588–2619 (the collision earlier findings flagged), including a fabricated `reworded` string (mock.ts:153–158) that looks exactly like successful ollama output. `getExplanation`'s catch-all (api.ts:357–363) returns `MOCK_EXPLANATIONS[reportId] ?? null` on **any** fetch error (network, 12 s abort, 404, 409), and the card then renders it under the `"phrased by local LLM"` badge (triage-card.tsx:260–265, 278). The provenance label actively asserts a machine origin for text a human scripted. The mock selfcheck does verify score/span invariants of these fixtures (mock.ts:450–459) — the *shape* is validated, the *content* is invented.

**7. [MAJOR] There is no current validation artifact for the explanation layer: the only verify report is 17 days stale and ran against the MOCK classifier.**
`artifacts/explanations/verify_report.json` (mtime Sep 8 11:10) reports `template_correct 20/20, reword_success 20/20, all_spans_exact_substrings 20/20` — with `"model_version": "mock-0.1.0"` (line 14) and the **pre-bump template wording** (`"IOGP rules implicated:" / "Evidence phrases:"`), i.e. it validated a template that no longer exists. The real ONNX artifact was shipped Sep 8 19:32 (sif_multitask_int8.onnx mtime) with final metrics.json Sep 8 20:37 — both before the demo DB build (Sep 9), yet verify was never re-run against them. Worse, the harness is now **unrunnable as documented**: its `DEFAULT_CORPUS = artifacts/synthetic/clean_combined.jsonl` (precompute.py:56) is deleted (directory confirmed absent this session), so the `verify` gate cannot be re-run without restoring a corpus. Net: the explanation layer's only quality evidence predates the model, the wording, and the cache-key change.

**8. [MAJOR] The template can assert a confident score for text the model cannot read; the language caveat is an afterthought.**
Measured live: a pure-Hindi report describing a worker's hand crushed by drill pipe scored **0.0521**, and the explanation's leading sentence reads `"Triage score 0.05 is below the 0.66 review threshold."` with the only honesty signal as the **last** line: `"Advisory gates: language (language badge [devanagari]: non_ascii_ratio=0.79 (> 0.15))."`. The gray-state system does route this to review via the badge, but the explanation itself asserts the number first and the caveat last. For an Assam (Assamese/Hindi/Bodo) workforce this class of report is exactly the one where "why should I believe this score?" has the true answer "you shouldn't — the model cannot read it" — and the template never says that sentence. (Offline fix exists: AI4Bharat IndicTrans2, MIT-licensed, covers Assamese/Bodo — noted in earlier findings.)

**9. [MINOR] Cache key omits the rewording model identity; ollama entries are served "verbatim forever" by design.**
`explain_key` (explain.py:134–149) hashes text + prediction model_version + repr(threshold) + EXPLANATION_VERSION — not the reworder model (`qwen3:4b`) or the system prompt. Swapping the reworder silently serves old-model phrasing (explain.py:384–386 "served verbatim forever"). For a paraphrase-only layer this is tolerable, but it is an undocumented staleness vector: a reworder *change* cannot invalidate cache by mechanism, only by manual version bump — the exact discipline that just failed in production practice (finding 1).

**10. [MINOR] Doc/contract drift inside the module: `num_predict` 400 documented vs 300 sent; three threshold constants.**
The docstring contract (explain.py:8–10) specifies `"num_predict": 400`; the call sends `300` (explain.py:338). `REVIEW_THRESHOLD = 0.5` (explain.py:40), `routes.FLAG_THRESHOLD = 0.5` (routes.py:46), and the artifact-tuned 0.6581 coexist — mitigated because routes always passes `flag_threshold(clf)` and the threshold is hashed into the key (explain.py:134–137), but the a-priori constants can silently miskey harness entries if the artifact ever fails to load (fallback path keys with 0.5 while the runtime keys with the tuned point).

**11. [MINOR] Score display drift: explanation formats 0.998 → "1.00".**
Measured on report 4546: card score `0.998`, explanation `"Review trigger: triage score 1.00 crossed the 0.66 review threshold."` (explain.py:221–224 formats `:.2f`). Two numbers for one verdict on the same card is exactly the kind of nit a hostile reviewer uses to open the credibility question.

**12. [Verified good — worth protecting]:** the honest-abstention line `"No reliable supporting phrase could be isolated; inspect the full report before disposition."` (explain.py:250); the one-shot-corrective-retry-then-silent-fallback shape (explain.py:329–355) with the error fed back into the prompt; the injected-transport test seam (explain.py:315, 373); the FALLBACK_TTL bounded-stall doctrine (explain.py:49, 383–388 — verified coherent with the re-save at 416); and the strongest anti-hallucination control of all — **the LLM never receives the report text**, so by construction it cannot introduce facts, severities, or recommendations the template didn't state (explain.py:118–122, with a measured rationale comment). Also live-verified coherent: the template's implicated-rule logic reads the same `RULE_DISPLAY` thresholds the classifier overwrote at load (classifier.py:289–291), so template numbers and `/rules` output cannot disagree in-process.

## Root cause (blocker, finding 1)

**The `EXPLANATION_VERSION` cache-busting suffix was added after the demo DB was built, and the required cache rebuild was never run.** Evidence chain:

- `git show 4cd1b09:app/explain.py:88–93` — the demo-build-era key: `sha256((text + "\x00" + model_version + "\x00" + repr(threshold)).encode("utf-8"))` — **no version component**.
- `git show afe32ad:app/explain.py:50` — current: `EXPLANATION_VERSION = "v3-rule-aware-evidence"`, hashed as a 4th field (explain.py:138–148). Same commit rewrote the template wording (`"is below the 0.66 review threshold"` etc.), so the bump was *correct* — stale-flag-wording protection was the intent (explain.py:135–137).
- `demo_pre.db` mtime 2026-09-09 22:48 (cache entries `created_epoch` 22:46:18–22:48:28, verified in-db) predates the version-string change; no rebuild or migration ran afterward; `run.sh` does not precompute explanations (grep: no hits).
- Runtime consequence measured live: reports 4546/4544/4542 return `cached: false`; current-formula keys reproduce 0/63 cached entries.
- Compounding: the 63 orphaned payloads embed pre-bump wording (`"Evidence phrases: ..."` in all 63 templates — verified), so even a key hit would serve wording inconsistent with a fresh `render_template`. The version constant did its job; the *rebuild step* was skipped, and nothing in the system detects dead entries — `/api/health` (main.py:40–49) exposes no cache stats, so a 0% hit ratio is invisible.

**Secondary root cause (finding 7):** the validation gate (`precompute.py verify`) depends on a corpus file that was deleted from `artifacts/synthetic/`, so the layer lost its only re-validation path at exactly the moment its template and key changed.

## Gaps vs production (decision-grade credibility)

- No audit trail binding displayed explanation content (+provenance+timestamp) to reviewer identity — the compliance replay does not exist.
- No counterfactual / "what would change this verdict" anywhere in the explanation.
- No plain-language calibration: metrics.json carries precision 0.80 @ recall 0.97 at the 0.66 point, but no verdict ever states it.
- No enforcement that reworded keeps rule numbers, gate advisories, or the 2–3 sentence limit.
- No cache observability (hit ratio, key-version) or migration tooling; dead entries are silent.
- No opt-in persistence of the exact explanation served (even a `?explain=1&persist=1` snapshot would be enough for replay).
- Server worst case (~17 s) exceeds the client's 12 s budget — the fallback the user actually experiences is "unavailable", not the template.
- Language-limited scoring never surfaces in the leading explanation sentence (Hindi/Devanagari gray-only, no translation — consistent with earlier finding 4).
- Layer validation is stale (mock-based) and the harness is unrunnable; the strongest current quality evidence is this session's spot-checks.

## Recommendation

- **KEEP `render_template` as the product** — deterministic, prediction-only, exact-substring evidence, honest abstention; it already satisfies 3 of the 4 real-XAI requirements (faithful evidence, calibrated numbers from one source, abstention).
- **FLIP the default `SIF_EXPLAIN_LLM` to 0** (`config.py:83`) — the reworder adds zero information by construction (template-only prompt, explain.py:118–122); it is pure phrasing risk for 3 GB RAM and a 2×8 s latency tail.
- **REBUILD the explanation cache** with the current key + template before any demo (or purge the 63 dead rows), and **ADD cache hit-ratio to `/api/health`** so a 0%-hit cache can never go unnoticed again.
- **ADD digit-boundary validation for rule probabilities and gate advisories** in `_validate` — same technique as the score check (explain.py:283–290); require non-empty `spans_quoted` for flagged verdicts.
- **ADD an explanation snapshot to `POST /review`** — persist `template, reworded, spans_quoted, source, cached, model_version, threshold` alongside the override — this single change makes reviewer decisions replayable for compliance.
- **ADD one template line of calibration + what-would-change-it**: "Tuned cutoff 0.66 (precision 0.80, recall 0.97); a report crosses review at ≥0.66 or on any gray-state gate."
- **LEAD with the language caveat** when the language gate triggers — the first line must say "score not valid — text outside supported languages", not bury it in the advisory footnote.
- **MERGE the version-bump with the rebuild harness**: restore or repoint `precompute.py`'s `DEFAULT_CORPUS` (deleted), and make `verify` run against the real artifact as a ship gate.
- **REMOVE the fabricated `reworded` values from `MOCK_EXPLANATIONS`** (null them) — scripted text must never wear the "phrased by local LLM" provenance badge on a safety surface.
- **FIX the `routes.py:102–104` comment**: the 8 s cap is per attempt, not per call (measured 17.5 s worst case).
- **ROUND the display consistently** (either 4-dp everywhere or same rounding in card and explanation) to kill the 0.998 → "1.00" mismatch.

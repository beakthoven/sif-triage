## Findings

1. **BLOCKER — corpus not reproducible from the repo; sources gitignored then deleted.** `.gitignore` line `artifacts/` excludes everything; `data_pipeline` defaults point to `artifacts/asrs/asrs-aviation-reports-train.jsonl` (build_corpus.py:299, missing), `artifacts/synthetic/{raw,clean,raw_v2}` (qa_synthetic.py:41-42, pattern_mine.py:33-36, missing), `artifacts/corpus/*` (missing). Surviving outputs (embeddings, patterns, models, seed DB) are outputs only. Impact: a reviewer cannot regenerate the training corpus; the only corpus evidence on disk is `corpus_ids.jsonl` (ids+source, no text, no labels).
2. **BLOCKER — 63.5% label prevalence is a corpus-composition artifact (root cause of the 71% flag rate; see dedicated section).** Measured chain: raw OSHA B_middle 65.30% overall (oiics_maps self-check this session); embedded corpus 44,730/70,398 = **63.54%** positive; masked-v2 test prevalence 0.6423 with tuned op flag_rate **0.7826** (models/masked-v2/metrics.json); packaged seed DB 4,548 rows → **70.1% flagged at the shipped op** (3,186/4,548), 71.6% at a-priori 0.5. The live figure (3,587/5,056 = 70.9%) is the same seeded DB plus ~500 session ingests. Literature anchor (~20% of recordables carry SIF potential) is not represented anywhere in the corpus.
3. **MAJOR — patterns.json is a saturated static artifact served before live data. CONFIRMED by direct read:** all 197 `site_x_activity` cells have `sif_rate=1.0` and `lift=1.499` — single distinct values in BOTH `patterns.json` and the `patterns.db` precomputed table (`patterns_mine` base_rate 0.6673; lift = 1.0/0.6673 = 1.499 exactly). `activity_x_barrier` has only two rate values {0.0, 1.0}. Serving order confirmed at app/routes.py:329-331: `pre = _precomputed_patterns(kind); if pre is not None: return …` — the live-DB aggregation below is dead code while the file exists. Mechanism: mining runs ONLY on the synthetic facet corpus (pattern_mine.py:33-36); the generator labels every positive row SIF (6,024/9,027 = 0.6673), positives concentrate in ~197 site×activity template cells that each clear min-support 10, negatives fall into cells below n≥10 (density seed: 4,510 cells, sums to 9,027) → every surviving cell is pure-positive → rate 1.0 → lift is a constant ratio. It can never change with real ingests. Known internally: runs/run2/day2/final_audit_ps_compliance.md:75 ("All 197 site×activity cells are rate=1.0, lift=1.499"). Fix: invert serving order (live DB first, file as cold-start seed), mine patterns on live ingests, and rank by Wilson CI lower bound; generator must place negatives into cells or mining must include the negative register.
4. **MAJOR — train/serve masking skew.** masking.py is applied at build time (train/val/test `masked_text`, all rows) and self-checks pass, but runtime scoring feeds the **raw** user text: app/routes.py:67 `pred = clf.predict(text)`; grep for `mask_text|masked_text` across `app/*.py` returns zero hits. The shipped model is trained on masked text (masked-v2). Result: input distribution at serve time (`[OUTCOME]`-free) differs from training (`[OUTCOME]` present in 75.3% of rows). The ablation evidence says unmasked scoring is not worse (operating_point.md: AUC 0.8712 unmasked vs 0.8629 masked on full test; McNemar n.s.), so either mask at serve or retrain unmasked — but the current mismatch is undocumented at the serving boundary. gates.py:63 does mirror the masker stems, but only for the negation gray-gate, not for scoring.
5. **MAJOR — seeded live DB is the training corpus itself; 59.7% of "live" reports banner as near-dups of their own training rows.** Packaged `seed/demo_pre.db` reports are synthetic-register texts; predictions' gate_states show `near_dup … cosine=1.000 with index row syn-neg_j-0030` etc.; 2,713/4,548 (59.7%) have near_dup triggered. D24's `--exclude-ids` (embed_corpus.py:12-17) excluded only the 13 demo attack cards, not the ~9k synthetic register rows seeded as the live corpus. Impact: the near-dup banner (a memory-not-generalization detector) is firing on the demo's own seed — the opposite of its intent on this data.
6. **MAJOR — flag operating point tuned on a 64%-positive derived-label distribution.** `artifacts/models/masked-v2/metrics.json → operating_point_test_tuned`: raw 0.74640 / calibrated 0.65811, P 0.8000, R 0.9748, flag_rate 0.7826, n=17,731, prevalence 0.6423, tuned 2026-09-08 on single-text scores (D27), selection "max recall s.t. precision ≥ 0.80". Stored as a versioned artifact and loaded at runtime (app/classifier.py:282, `_load_flag_threshold`, fallback 0.5) — wiring is good; but P≥0.80 is only achievable on a 64%-positive test set. At ~20% true SIF prevalence the same threshold yields ≪0.80 precision; the threshold transfer was never measured on a realistic-prevalence eval. Near-dup banner threshold 0.91 is hardcoded in app/config.py:69 (with provenance comment) and matches `threshold_report.json` `chosen_threshold=0.91` (recall_b 0.9541, fpr_a 0.0, fp_rate_c 0.0).
7. **MINOR — spec self-inconsistency on prevalence, flagged in code but never resolved.** `spec/label_spec.yaml:218` `target_train_prevalence: 0.40` vs frozen ratios (lines 212-217) arithmetically implying ~65%; build_corpus.py:409-410 writes a `spec_note` into splits.json; merge_corpus.py:25-27,185 and the day-1 report §3 flag it for adjudication. The 0.40 target was the correct instinct (moving toward the ~20% literature prior); the frozen mix ratios won and 63.5% shipped.

## Root cause: the 71% flag rate

Verdict: **CONFIRMED as a corpus-composition artifact, refined with session-measured numbers.** Chain, each link verified this session:

1. **Source selection.** OSHA Severe Injury Reports are severe-injury-only surveillance (hospitalization/amputation/eye-loss inclusion). Deriving "SIF potential" from high-energy mechanism codes (B_middle: contact-6x, fall-from-height-4x, fire/explosion 31/32, electrical 51) therefore labels **65.30% of all 105,996 rows positive** (v1 65.52%, v2 64.21% — oiics_maps.py self-check, PASS, this session). No amount of downstream mixing escapes this anchor: any OSHA-heavy corpus is ~65% positive.
2. **Mix amplifies, not corrects.** Frozen ratios 55/15/15 + synthetic 10/5 (spec:212-217) produce train prevalence 63.5%: embedded index = osha_positive 38,711 (54.99%) + synthetic_positive 6,019 (8.55%) = **44,730/70,398 = 63.54%**; negatives = asrs 12,035 (17.10%) + low-energy OSHA 10,632 (15.10%) + synthetic 3,001 (4.26%). Synthetic is 66.7% positive itself (patterns.json base_rate 0.6673). The spec's own 0.40 target was overridden by the ratios (F7).
3. **Eval inherits the same distribution.** test.jsonl is natural v2 OSHA → prevalence 0.6423 (n=17,731, metrics.json). The tuned op (P≥0.80 on that set) has flag_rate 0.7826 on its own eval. Classical baseline confirms: test sample prevalence 0.642 (baselines/classical_report.md).
4. **Serving distribution.** The live/demo DB is seeded from the synthetic OIL register (demo_pre.db, source `pre-state-seed`, 4,548 reports; texts are generator-style OIL narratives; near-dup details cite `syn-*` index rows). Recomputed from the packaged copy: **70.1% flagged at the shipped calibrated op 0.6581**; 71.6% at a-priori 0.5 — the score distribution is bimodal (median 0.958, p25 0.056), so threshold choice barely moves it. The reported 3,587/5,056 = 70.9% is this seed plus ~500 live-session ingests.
5. **Why the model is confidently wrong about prevalence:** it learned a 63.5%-positive prior; its calibrated scores put most register reports at >0.95. The problem is not the classifier or the threshold — at ANY threshold in 0.5..0.66 the seeded DB flags 70-72%. The problem is what "positive" means in the corpus: OSHA SIR has no routine-recordable stratum, ASRS is aviation near-miss (different register), and synthetic negatives are only 4.26% of the corpus.

Per-sub-question:
(a) Yes — prevalence is a corpus-composition artifact of OSHA's severe-injury-only inclusion criterion amplified by the 55/15/15 mix. (b) Contribution to the 70,398-row index: osha_positive 54.99%, asrs_negative 17.10%, osha_low_energy_negative 15.10%, synthetic_positive 8.55%, synthetic_negative 4.26%; positives are 86.5% OSHA-derived. (c) To reach a realistic near-miss register the pipeline needs: a negative-dominant register corpus (scale synthetic negatives from 3,001 and generate from near-miss/UA-UC registers, not severe incidents), a positive share moved toward 20-30%, a re-tuned operating point evaluated at realistic prevalence (gold set is the natural candidate), and re-derived pattern artifacts. OSHA cannot supply routine-recordable negatives; no public US register matches OIL's — synthetic negative mass must carry that stratum. (d) Temporal split is clean (hard 2023-12-31 boundary, exact-dedup pre-split, J≥0.5 boundary screen dropping 0.068%, employer-grouped group-disjoint val); residual employer overlap 35.29% is accepted and disclosed; the deeper problem is distributional (test = same 64% positive artifact), not label leakage. (e) Verbatim + cross-boundary near-dup leakage is handled; within-train near-dups are not screened (exact only) — minor residual; synthetic-vs-corpus and synthetic-vs-synthetic dedup is rigorous (qa_synthetic stages 4-6, df-capped shingles, 0 corpus-J drops in round 1).

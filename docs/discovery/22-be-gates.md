Each gate returns `GateState{name, triggered, detail, action}` where action ∈ `badge|gray|block`; `block` is reserved and never used (`schemas.py:68-73`, `gates.py:3-7`). ## Findings

**F1 (major) — near_dup drowns `/api/metrics/summary`, but the premise "demote near_dup from gray" is inverted: it is already badge-only.** The trigger at `gates.py:271` returns `action="badge"`; the frontend honors the vocabulary (`feed.tsx:55-56`: `.filter(gate => gate.triggered && gate.action !== "badge")`, badge gates annotate the triage card, `triage-card.tsx:24,47,116`). The drowning is therefore (a) metric-level — `metrics_aggregate` counts all triggered gates identically regardless of action (`storage.py:485-489`), so a badge that fires on 59.7% of rows is 93.3% of the summary's "gate triggers", making the 186-row gray queue invisible; and (b) attention-level — a tripwire banner that fires on 60% of all rows is discounted by any reader, red-team judge included. Why it matters: the summary number a judge reads ("gate triggers: near_dup 3,021") does not describe any user-visible routing behavior.

**F2 (blocker, for metrics credibility) — gate decisions are frozen snapshots; the metrics endpoint reports a mix of two gate-code generations.** `predictions.gate_states` is an opaque JSON snapshot written once at ingest (`storage.py:236-251`) with no schema version; `metrics_aggregate` counts those snapshots (`storage.py:481-489`). Measured consequence: 4,548 seeded rows carry an 8-gate schema (`min_length…well_control_watch` — `chunked_low_score`/`severity_watch` never evaluated on them), so the endpoint reports `severity_watch: 5` while current code on the same texts yields 50 (45 hidden FPs-of-the-metrics). Threshold evolution compounds this: the operating point moved 0.5 → 0.658 (`metrics.json`), which silently re-scopes `confidence`, `well_control_watch`, `severity_watch` (all take `flag_thr`) without any recomputation; the `gates.py:80` comment still cites "49/4557 rows (1.1%)" from the old point. Why it matters: `/api/metrics/summary` is the demo's credibility instrument; today it cannot answer "what would the current gates do on this data?" — and a judge who recomputes will find 10× the reported severity_watch count.

**F3 (major) — near_dup carries zero triage signal on this deployment, and it is the only gate telling the truth about it.** Of 3,021 parsed trigger details, cosine is **1.000 at p25/p50/p75/max**; matched corpus ids are `syn-*` 2,998 vs `osha-*` 23; zero session-tier matches. The live rows come from `artifacts/demo/bulk_ingest_5k.csv` (5,050 rows; `.run/bulk_ingest_client.py:2-3`, `.run/bulk_ingest_result.json` "accepted: 5050") and match `syn-*` training-corpus rows **verbatim** (sample #1 "Green algae made the ramp near the pump house very slippery…" == CSV row 2 == `syn-neg_j-0030` @ cosine 1.000). So the banner built to catch the "memory, not generalization" paste attack (`gates.py:247-252`) fires by construction on ~60% of the population: the corpus *is* the training family. Corollary the queue numbers inherit: median live score 0.958 and the 71% flag rate are measured on memorized data. The gate is not lying; the data is.

**F4 (major) — the negation gate is score-blind and fires on the standard Indian near-miss closing register.** `gate_negation(text)` takes no score (`gates.py:162`); its docstring claims "Negated high-severity-looking reports are forced to gray review" (`gates.py:29`) but nothing in the implementation checks severity-looking. Measured: all 42 triggers are rows whose outcome language is correctly negated ("no damage", "no harm", "no injury") — 27 of them already score ≥ 0.658 (gray adds nothing to a flagged row) and 13 score < 0.40, i.e. reassurance boilerplate on no-injury events converted into review load with zero misclassification risk to prevent. The gate as coded measures "report contains the polite closing sentence", not "negated SIF". Two mechanical false positives were measured from a stem collision: `_OUTCOME_STEMS` contains `"surg"` (surgery) which prefix-matches pressure-`'surge'` (`gates.py:64,110`), graying #416 ("remote start … was not inhibited. Pressure surge came") and #566 ("compressor continued without [tripping] anti surge controller"); 2 rows in the corpus hit this surface.

**F5 (blocker for production, untested in demo) — the language gate is a designed dead end for the Assam workforce, and it is currently inert.** Trigger: any Devanagari char (`gates.py:203`) or non-ASCII ratio > 0.15 (`config.py:72`) → gray with "Report text is never machine-translated live (adjudicated)" (`gates.py:198`). Measured: **0 Devanagari rows** in the DB (only the smoke test + one mock fixture exercise it) — so this is a design-level gap, not a measured load. Under this gate a Hindi/Assamese report can never be triaged, only preserved. Verified remedy facts (from the [IndicTrans2 README](https://raw.githubusercontent.com/AI4Bharat/IndicTrans2/main/README.md)): all 22 scheduled Indic languages incl. **Assamese (`asm_Beng`)**, **Bodo (`brx_Deva`)**, Hindi (`hin_Deva`); model checkpoints **MIT**; distilled checkpoints exist (`indictrans2-indic-en-dist-200M` for Indic→English, `indictrans2-en-indic-dist-200M`) with **official CTranslate2 (CT2) ports for efficient inference**. Feasibility assessment (sizes/latency are arithmetic/engineering estimates, **not measured by me**): ~200M params ≈ 0.4 GB fp16 / ~0.2 GB int8 on disk — same order as the vendored MiniLM index; CT2 int8 CPU on this 16-thread box ≈ sub-second to low-single-digit seconds per short sentence, acceptable for **ingest-time** translation (the D25 ingest path already spends 947 s / 5.33 rows/s). Integration path: keep `gate_language` as the detector; on trigger, translate offline (IndicTrans2-indic-en-dist-200M via CT2 int8), classify the English, persist original + translation + provenance, and downgrade the gate to badge ("machine-translated, review original"). Note the prior rejection "Live translation was measured and rejected (4B gibberish-prone)" (`docs/deck/qa_prep.md:185-186`) tested the Ollama `qwen3:4b` LLM — a different, weaker tool for this job than a dedicated NMT model; the no-cloud constraint survives because CT2 runs in-process offline (new pip dep, wheel-installable). Also relevant: **negated Hindi is unhandled** — `_TOKEN_RE = [A-Za-z0-9]+` (`gates.py:104`) yields zero tokens for Devanagari text, so `gate_negation` returns immediately (`gates.py:169-171`); moot today because the language gate grays those rows first, but it means negation handling is English-only, full stop.

**F6 (major) — well_control_watch grays routine maintenance under the re-tuned threshold.** 29 triggered rows; ~19 have score < 0.1 and are routine wellhead vocabulary mentions — e.g. #123 "Christmas tree wing valve greasing done at wellhead BGR-12. Valves operating smooth, no leak se…" scores 0.006 and is grayed with "rare high-consequence domain, automated screening defers". The barrier tag (`classifier.py:110-127`: `workover`, `wellhead`, `christmas tree`, `h2s`, `bop`…) fires on any mention; the flag threshold rose 0.5 → 0.658, widening this gate's trigger surface without re-measuring (the comment cites probe results at the old point, `gates.py:284-286`). Only ~4 of the 29 (#3001 0.508, #4388 0.551, #4738 0.657, #3876 0.643) look like genuine near-miss well-control events.

**F7 (major) — threshold sprawl inside and around the gates, plus fabricated gate output on the client.** The gates consume five different cutoffs: artifact `threshold_calibrated=0.6581` (severity_watch, well_control_watch), gray band [0.40, 0.60] from cfg (confidence), **hardcoded 0.40** in `chunked_low_score` (`gates.py:307`, duplicating `cfg.gray_band_low`), near-dup 0.91, and the client's own `bandFor` 0.7/0.4 (`api.ts:129-131`, contradicting its comment "Thresholds match the server's gray band"). Separately, on any fetch failure `api.ts:288-307` returns a **synthesized score 0.5 + "MODERATE" band + a fake `confidence` gate** with detail "API unreachable — offline demo mode" — invented model output and invented gate state on a safety-critical surface, same family as the mock-fixture collision (prior finding #8) but a distinct, one-file fix. Measured consequence of the sprawl on this DB: 25 rows sit in the (0.60, 0.658) no-man's land — no gate triggers, not flagged, auto-green; the gray band itself catches only 78 rows (1.5%) because the score distribution is bimodal (p10 0.0099, p50 0.958), so a fixed mid-band is nearly inert.

**F8 (minor) — zero-fire gates are invisible in metrics.** `gate_trigger_counts` is a dict of fired gates only (`schemas.py:236-237`); `language` and `chunked_low_score` never appear, so "0 fires" is indistinguishable from "gate absent" for a reader of the endpoint.

**F9 (minor) — silent mirror-drift is structurally invited.** `gates.py:58-62` duplicates the masking stems ("mirrored here, not imported") and `classifier.py:106-108` mirrors the spec's well-control keywords; no test asserts either mirror equality (grep across `app/`, `tests/`, `app/tests/` found none). The `'surg'~'surge'` collision (F4) shows the cost of frozen duplicated lists drifting independently.

**F10 (minor) — `extract_site` is conservative and deterministic but untested and under-wired.** Its three-tier design (labelled header → prepositional phrase with cue → first-clause cue, `report_metadata.py:31-43`) is sound and honest ("otherwise leave the site unknown"), but it has zero tests and is only called on the persist path; bulk ingests never benefit from it.

**F11 (minor) — near_dup is the only non-deterministic gate and the order is position-coupled.** `gate_near_dup` merges a mutable session tier (`storage.py:571-581`, appended on every ingest) into a fixed corpus tier, so the same text re-classified later can flip; testable only with seeded fixtures (`near_dup_embed_check.py`). Gate order is load-bearing by index (`api_smoke.py:133` addresses `gate_states[4]`), forcing new gates to be appended last "so existing positions hold" (`gates.py:395-397`).

**F12 (minor) — `block` is reserved and never used** (`gates.py:5-6`, `schemas.py:71-72`), `action` defaults to `"badge"`. Honest today; a latent foot-gun if a future gate ships with the default action instead of an explicit decision.

## Root cause (blockers)

**F2 — stale gate metrics.** The chain: gates are pure functions (deterministic, recomputable at 244 µs/row) → but their outputs are persisted as opaque JSON snapshots (`storage.py:247`), the schema has no version marker, and the summary counts snapshots (`storage.py:481-489`) instead of behavior. Thresholds live partly outside the snapshot (`flag_thr` is passed at run time, `routes.py:70-73`), so any operating-point or gate-code change de-syncs stored states from code silently. The deterministic-pure-function design makes the fix trivial — recompute-and-backfill over 4,548 rows costs ~1.1 s once — but nothing in the system triggers it.

**F3 — near-dup saturation.** Not a gate bug. The seed chain is: `artifacts/demo/bulk_ingest_5k.csv` (synthetic OIL-register rows) → bulk `/api/ingest` → DB, while the near-dup base index is the training corpus (`corpus_index_meta.json`: "n_rows": 70398, corpus = `artifacts/corpus/train_final_v2.jsonl`), whose synthetic slice shares the same generator family as the demo CSV. A 0.91 threshold measured for dup-pair recall/FPR on pairs (`threshold_report.md`: "0.91 … max threshold with recall(b) ≥ 0.95 and FPR(a) ≤ 0.01") is therefore applied to a population that is largely near-copies of the index by construction — p50 cosine 1.000. The gate correctly discloses that the "live" queue is memorized data; the credibility damage flows from the data provenance, not the threshold.

## Gaps vs production

- No per-gate precision/recall against human review outcomes: the overrides table holds **1** row, so gray actions have essentially never been audited by a human decision; gate FP rates (negation boilerplate, well-control keyword coincidence, drill) are unquantified against gold.
- No gate-state schema versioning, no re-evaluation/backfill path; metrics can silently contradict current code (proven F2).
- `gate_trigger_counts` conflates annotate-only and routing dispositions; zero-fire gates are invisible (F1, F8).
- No offline Indic translation path; language gate is a terminal gray for an entire class of field reports (F5); Hindi negation coverage is zero by construction.
- No suppression/dedup of repeated near-dup banners across re-display; the banner's 60% base rate destroys its evidentiary value (F3).
- No time/cadre dimension on gate metrics (out of my files but blocks trend-level humility reporting).
- No test for `report_metadata`; no mirror-equality tests for the duplicated frozen lists (F9, F10).

## Recommendation

- **KEEP** the gate framework as-is (pure functions, fail-safe error wrapper, advisory semantics) — it is the most defensible subsystem in the backend, and the FE already consumes `action` correctly (`feed.tsx:55-56`).
- **KEEP** near_dup as `badge` — do *not* demote/gray it; the assignment premise is inverted, it is already badge-only.
- **REMOVE** badge-only gates from `gate_trigger_counts` (or report counts split by action) — the 186-row gray queue must be the headline, not the 3,021-event banner.
- **ADD** a `gate_schema_version` on persisted `gate_states` plus a one-shot backfill that recomputes the 4,548 old rows with current code (~1 s; pure functions make it safe) — or compute gate metrics live and cache.
- **ADD** a score parameter to `gate_negation` (gray only when the score was in the band or above flag threshold; badge elsewhere) — removes the 13 measured no-injury-boilerplate grays and matches the gate's own docstring.
- **FIX** the `'surg'` stem collision (exclude token `surge`, exactly as `'sever'` is token-exact for `'several'`) — 2 measured false grays.
- **REPLACE** the hardcoded `0.40` in `chunked_low_score` with `cfg.gray_band_low` — one config to change, no silent divergence.
- **ADD** offline IndicTrans2-indic-en-dist-200M (CT2 int8) translation at ingest; language gate degrades gray→badge; keeps 100% local, zero cloud; ~0.4 GB fp16-class model alongside the existing MiniLM index.
- **ADD** zero-fire gates to `MetricsSummary` (full name→count including 0) so "never fires" is measurable.
- **MERGE** the duplicated frozen lists (masking stems, well-control keywords) into one shared, versioned declarative file (reuse the `spec/label_spec.yaml` pattern) imported by both sides, with a startup equality check — and **REJECT** a rule-engine library: the gates need embedding-index and classifier-threshold access and fit in 423 lines; a DSL + new dependency would add complexity, not remove it.
- **REMOVE** the FE's fabricated fallback prediction + fake `confidence` gate (`api.ts:288-307`) — surface an explicit "offline" state instead of inventing gate output on a safety surface.
- **ADD** unit tests for `extract_site` and a gates↔masking stem-equality test.
